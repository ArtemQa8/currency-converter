## 📖 О проекте
Данный проект представляет собой сервис для конвертации валют, использующий API Центрального Банка РФ. 

Программа реализована в двух интерфейсах: 
1. **REST API** (на базе Gin) - для взаимодействия с внешними клиентами.
2. **CLI (командная строка)** - интерактивное меню для пользователя с выводом сводки курсов и истории.

Основная задача, которая решалась в ходе работы, - обеспечить отказоустойчивость. Сервис должен продолжать работать и возвращать актуальные (или последние известные) курсы, даже если внешнее API недоступно или база данных временно не отвечает.

## 🏗 Архитектура и принципы работы
Проект разделен на слои для удобства поддержки и тестирования:
*   **Transport:** HTTP-сервер на базе `Gin` (для внешних клиентов) и интерактивный CLI.
*   **Service:**  Ядро приложения, отвечающее за математику кросс-курсов, обработку ошибок и оркестрацию цепочки источников данных.
*   **Repository:** Реализации интерфейсов для работы с API ЦБ, Redis, PostgreSQL и локальным файлом.
*   **Domain:** Базовые сущности (`Currency`, `Rate`), не зависящие от внешних библиотек.

### 🔄 Цепочка отказоустойчивости (Fallback)
Логика получения курса выстроена следующим образом:
1.  **Redis (Cache):** Сначала проверяем кэш (TTL 3 часа). Если данные есть - отдаем их мгновенно.
2.  **API ЦБ (Primary):** Если в кэше пусто, идем в ЦБ. Забираем данные сразу по всем валютам и сохраняем в кэш и в базу.
3.  **PostgreSQL (History):** Если ЦБ недоступен, берем последний сохраненный курс из базы данных.
4.  **Local File (Snapshot):** Если база лежит, читаем из локального JSON-файла.
5.  **`//go:embed` (Seed):** Крайний случай - если всё упало, отдаем вшитые в бинарник аварийные курсы.

## 🧠 Архитектурные решения (ADR)
1.  **Выбор PostgreSQL:** Выбран благодаря строгой типизации (для финансовых данных используется `NUMERIC(15,6)`), поддержке уникальных индексов (защита от дублей) и удобной системе миграций (`goose`).
2.  **Использование `shopspring/decimal`:** Стандартный `float64` не подходит для финансовых расчетов из-за ошибок округления. `decimal` гарантирует точность.
3.  **Атомарная запись файла (tmp + rename):** При сохранении данных в JSON мы пишем их во временный файл, синхронизируем с диском и только потом переименовываем. Это защищает основной файл от повреждения при внезапном падении программы.
4.  **Использование `sync.RWMutex` в файловом провайдере:** Предотвращает состояние гонки (Race Condition), позволяя нескольким горутинам читать файл, но блокируя доступ при записи.
5.  **`singleflight` для запросов к ЦБ:** Защищает внешнее API от большого количества одновременных запросов при истечении TTL кэша (чтоб нас не забанили за ddos).
6.  **Банковское округление (`RoundBank`):** Используется для минимизации накопления ошибок при массовых конвертациях.
7.   **Graceful Shutdown:** HTTP-сервер корректно завершает работу по `Ctrl+C`, давая активным запросам время завершиться.

## 🔧 Адаптация конфига линтера (`.golangci.yml`)
В ходе разработки проект был переведен на современную версию `golangci-lint` (v2), так как старая версия не поддерживала Go 1.27. Из-за этого конфиг пришлось адаптировать под новый синтаксис. 
Были внесены следующие изменения:
*   Добавлена обязательная директива `version: "2"`.
*   Параметр `disable-all: true` заменен на `default: none` (изменение синтаксиса v2).
*   Перенесены линтеры `gci`, `gofmt`, `gofumpt` из блока `linters` в новый блок `formatters`.
*   Удален `typecheck` (в v2 он встроен в ядро и не включается вручную).
*   Удалены устаревшие линтеры `deadcode`, `structcheck`, `varcheck`, `ifshort`, `exportloopref` (они были удалены разработчиками и заменены общим линтером `unused`, который в конфиге присутствует).

## 📂 Важные особенности реализации
*   **Миграция `004_seed_history.sql`:** При первом запуске (после команды `goose up`) база автоматически заполняется историей курсов за последнюю неделю. Это сделано для того, чтобы не пришлось ждать, пока накопится история, для проверки `/api/history`
*   **Аварийные данные (`internal/repository/file/seed_rates.json`):** Файл вшит в бинарник через `//go:embed`. Он используется как последний рубеж обороны, если ЦБ, база и кэш одновременно недоступны.
*   **Снимок данных (`data/rates.json`):** Создается автоматически. Это локальный файл с последними курсами (запись происходит атомарно), который используется в качестве предпоследнего источника данных.
*   **Поддержка разного ввода:** В CLI реализован умный ввод. Понимает "100 баксов", "долларов", "$", "дол", а также слова на неправильной раскладке (например, `LJK` вместо `USD`). Доступно для Рубля, Доллара, Евро, Юаня, Йены, Воны. (`cmd/client/constants.go`)
*   **Умный выход:** В меню работают команды `выход`, `назад`, `exit`, `quit`, `back` (включая неправильную раскладку).
*   **Сводка в главном меню:** Показывает последний доступный курс Доллара и Евро, а так же их динамику по сравнению с предыдущим значением (цвет и стрелочки меняются в зависимости от того, вырос курс или опустился)
*   **Точность валют:** При выводе результата учитывается точность валюты (например, йена выводится без копеек, а рубль - с двумя знаками).

### 🌐 Доступные API ручки
*   `POST /api/convert` - конвертация суммы. Тело запроса: `{"amount": 100, "from": "USD", "to": "RUB"}`.
*   `GET /api/history?from=USD&to=RUB&days=7` - получение истории курса за N дней. (В данном случае курс доллара (USD) за 7 дней. Вторая валюта всегда рубль).

## 🚀 Запуск проекта

Для запуска вам понадобится **Docker Desktop** (должен быть запущен) и установленный **Go**.

### Шаг 1: Подготовка
Создайте файл конфигурации из шаблона:
`cp .env.example .env`
(Или просто переименуйте `.env.example` в `.env`)

### Шаг 2: Запуск
*   **Вариант А: Полный запуск в Docker**
1. Соберите и запустите контейнеры:
   ```bash
   docker compose -f deploy/docker-compose.yml up -d --build

2. Примените миграции к базе данных (из корня проекта):
   ```bash
   goose -dir migrations postgres "postgres://converter:converter@localhost:5432/converter?sslmode=disable" up

3. Запустите CLI-клиент (он работает локально и стучится к серверу в Docker):
   ```bash
   go run ./cmd/client

*   **Вариант Б: Локальный запуск**
1. Поднимите только базы данных (без сервера):
   ```bash
   docker compose -f deploy/docker-compose.yml up -d postgres redis

2. Примените миграции:
   ```bash
   goose -dir migrations postgres "postgres://converter:converter@localhost:5432/converter?sslmode=disable" up

3. Запустите сервер (в первом окне терминала):
   ```bash
   go run ./cmd/server

4. Запустите CLI (во втором окне терминала):
   ```bash
   go run ./cmd/client

## 🛠 Шпаргалка по командам

### Управление контейнерами
*   Запустить всё (сервер + базы): `docker compose -f deploy/docker-compose.yml up -d --build`
*   Запустить только базы: `docker compose -f deploy/docker-compose.yml up -d postgres redis`
*   Остановить всё: `docker compose -f deploy/docker-compose.yml down`
*   Остановить и удалить данные (полный сброс): `docker compose -f deploy/docker-compose.yml down -v`
*   Очистить базу Postgres (удалить все данные из таблиц): `docker exec -it converter-postgres psql -U converter -d converter -c "TRUNCATE TABLE rate_history RESTART IDENTITY;"`
*   Очистить кэш Redis: `docker exec -it converter-redis redis-cli FLUSHALL`

### Миграции базы данных (goose)
*   Накатить все миграции: `goose -dir migrations postgres "postgres://converter:converter@localhost:5432/converter?sslmode=disable" up`
*   Откатить последнюю миграцию: `goose -dir migrations postgres "postgres://converter:converter@localhost:5432/converter?sslmode=disable" down`

### Запуск приложения
*   Запустить сервер: `go run ./cmd/server`
*   Запустить CLI: `go run ./cmd/client`
*   Собрать бинарники: `go build -o bin/server ./cmd/server` и `go build -o bin/client ./cmd/client`

### Тестирование и покрытие
*   Запустить все тесты: `go test ./...`
*   Запустить тесты конкретного пакета: `go test ./internal/service`
*   Запустить тесты с детектором гонок (только Linux/Mac): `go test -race -count 100 ./...`
*   Сгенерировать файл покрытия: `go test -coverprofile="coverage.out" ./...`
*   Посмотреть покрытие в браузере (HTML): `go tool cover -html="coverage.out"`

### Линтер
*   Запустить проверку кода: `golangci-lint run`
